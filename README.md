# Yda Facet 01 — Mac アプリ（ネイティブ版の土台）

このアプリは、今の Web 画面（`web/facet.html`）をアプリのウィンドウに入れたものです。

- 版：0.3.0（同梱の Web 画面は、ビルドしたときの YDA のサイトの最新版）
- 第 1 段階なので、音はまだ Web 画面の中で鳴っています。
- 次の段階から、音の処理を少しずつネイティブのエンジンに移していきます。

## 中身

| ファイル | 役割 |
|---|---|
| `Source/Main.cpp` | アプリ本体。ウィンドウ、Web 画面、保存ダイアログ、MIDI、更新のつなぎ |
| `Source/MacBits.mm` | Mac 専用：画面の確認ダイアログ（OK／キャンセル）を Mac のダイアログで出す |
| `tools/fetch_screen.py` | ビルドのたびに YDA のサイトから最新の Web 画面を取ってきて `web/facet.html` にする（手で差し替える必要なし） |
| `web/last-screen.txt` | サイトに届かなかったときに使う、最後に分かっている画面のファイル |
| `CMakeLists.txt` | 組み立て方。JUCE 9.0.6 を自動で取ってきます。Intel と Apple Silicon の両方に対応し、macOS 11 以降で動きます |
| `.github/workflows/build-mac.yml` | GitHub の Mac で自動でアプリを作る手順 |

## アプリを作る（手元に Xcode は要りません）

1. GitHub に変更を上げたとき、Actions から手で動かしたとき、毎日 4:17（YDA のサイトに新しい画面があるときだけ）に「build-mac」が動きます（初回は 15〜25 分ほど）。
2. できたアプリは Releases の一番上（latest）に `YdaFacet01-mac.zip` として置かれます。
3. ZIP を開くと `Yda Facet 01.app` が出てきます。
4. 初めて開くとき：
   - まず右クリック →「開く」を試します。
   - 開けなければ、システム設定 → プライバシーとセキュリティ →「このまま開く」を押します。

Apple の開発者登録をしていないので、署名は手元用の簡易署名です。

## できること・確かめたこと（Linux 版で自動テスト済み）

- 画面は file:// で読み込みます。
  - 「安全な場所」として扱われ、AudioWorklet、localStorage、IndexedDB が使えることを確かめました。
  - 起動時に、こうした状態を `~/Library/Application Support/Yda Facet/boot.txt` に書き出します。おかしいときはこのファイルを見ればわかります。
- WAV、ZIP、.facet の書き出しは Mac の保存ダイアログで保存されます。
  - 2 MB ずつ分けて受け渡すので、大きな ZIP でも保存できます。5 MB の試験ファイルで、中身が 1 バイトも変わらないことを確かめました。
- 環境変数 `FACET_SELFTEST=1` を付けて起動すると、保存の自己テストをしてから終了します。

## Web 画面の自動更新（0.2.0）

- 起動して 8 秒後と、その後 6 時間ごとに、YDA のサイトの FACET のページを見に行きます。今は下書きテーマのプレビューを見ていて、公開後もそのまま使えます。
- 新しい画面が見つかると、裏でダウンロードします。画面の下に「新しい画面 vX があります」が出るので、［いま切り替える］か［次の起動で］を選べます。演奏中に勝手に切り替わることはありません。
- 受け取るのは、ストアのファイル置き場（cdn.shopify.com の Y/da のフォルダ）にある `yda-facet-01-X.Y.Z.js` だけです。中身が Facet の画面であることと、版番号が合っていることを確かめてから使います。
- 画面はいつも `~/Library/Application Support/Yda Facet/web/facet.html` から開きます。場所が変わらないので、保存した曲や設定は更新しても残ります。
- 更新の記録は `update.txt` に残ります。ネットにつながっていないときは、手元の最新の画面でそのまま動きます。
- 確かめたこと（Linux 版の自動テスト）：新しい版を見つける → ダウンロード → バーが出る →［いま切り替える］→ 新しい画面で起動。次の起動でも新しい画面のままで、保存も動きました。

## 0.3.0 で増えたこと

- **MIDI**：アプリの中の画面には Web MIDI がないので、アプリが Mac の MIDI を使って代わりに受け渡します。コントローラー・MIDI LEARN・MIDI 出力（クロックを含む）が使えます。先の時刻を指定した送信は、出口ごとのタイミング用スレッドがその時刻ちょうどに送ります。抜き差しは 1.5 秒ごとに確かめます。
- **確認ダイアログ**：画面の「よろしいですか？」（.facet の読み込みなど）が、Mac のダイアログで出るようになりました。0.2.0 では出ずに「キャンセル」扱いになり、読み込めませんでした。
- **アプリ本体の更新**：新しいアプリが GitHub に出ると、デスクトップの「Yda facet/native」フォルダ（なければダウンロード）に自動で保存し、画面に「新しいアプリがあります」のバーを出します。［フォルダを開く］で、そのフォルダが開きます。
- **アプリのアイコン**：`Resources/icon.svg`（ファセットの宝石と 16 のステップ）。ビルドのときに PNG にして入れます。
- **落ちたときの復元**：曲（画面が保存している内容）を 30 秒ごと、変わったときだけディスクにも写しておきます（新しい 12 個）。前回が途中で終わっていたら、起動時に「前回は途中で終了しました。HH:MM の自動保存から曲を戻しますか？」と出て、［戻す］で戻ります。
- まだできないこと：音の出口の切り替え（スピーカー／ヘッドホン）。画面の中の音は Mac の標準の出口から出るので、切り替えは音のエンジンをアプリ側に移す段階でできるようになります。

## 次の段階

1. 音のエンジンをネイティブ（C++）に移します。最初は CHAOS と重い音作りから始め、複数のコアで処理します。
2. AU / VST3 のプラグインを作ります。同じ画面と同じエンジンを使い、トラックごとの出口から DAW に直接パラ出しします。
3. 配布の準備：Apple の署名と公証（Apple Developer Program）を行い、JUCE のライセンスを確認します。
